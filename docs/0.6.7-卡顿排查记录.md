# 0.6.7 卡顿／检测后页面无响应排查

## 结论边界

用户确认故障为整个游戏页无响应。独立 Chrome 测试确认明显低帧率，但尚未复现完整追捕时整页无响应；不能宣称根因已定位或已修复。本次未改动游戏渲染、玩法、音频或存档设置，未刷新用户页面、关闭浏览器或重启现有进程。

## 已确认的测量

- 独立 Chrome，1280×800、DPR 1，QA 无存档模式。
- 实际 WebGL 渲染器：ANGLE / Intel Arc Graphics / Direct3D11，非 SwiftShader。
- PLAYING 初始引擎 FPS 为 24；后续 RAF 帧间隔中位数约 50ms，即约 20 FPS。
- 平静阶段 164 个帧间隔：中位数 49.8ms、P95 75ms、最大 158.3ms。
- 怀疑阶段 44 个帧间隔：中位数 50ms、P95 66.7ms、最大 92.1ms。
- 恢复阶段 157 个帧间隔：中位数 50.1ms、P95 133.5ms、最大 166.7ms。
- 上述游戏阶段未记录超过 1 秒的帧间隔；等待检测条件超时后，页面仍可执行脚本并返回状态。
- 启动阶段记录约 23.7 秒主线程长任务，不属于已确认的检测触发卡死，也尚未拆分其加载／编译耗时。
- 输入路线进入短暂怀疑后恢复，未触发预期完整追捕。因此检测条件超时是路线／条件未满足，不等于页面无响应。
- 1920×1080、DPR 1.5 场景因独立 QA 服务连接被拒绝未执行，不能用于性能结论。

## 系统与日志

- Intel Arc 驱动 31.0.101.5522，系统另有虚拟显示适配器；不能据此归因驱动。
- 检查时物理内存约 31.5GiB，可用约 12GiB，未显示系统内存耗尽。
- 检查的前一小时 Windows 日志未发现相关 GPU 重置（4101）或 Chrome／Edge／Godot 崩溃／挂起（1000／1002）事件；不排除未被系统记录的标签页卡死。
- 用户现有浏览器未开放远程调试，不能直接取得故障标签页控制台或性能轨迹。
- 原有退出阶段 16 个 ObjectDB／8 个资源警告仍未解决，但无证据表明其导致本次运行中卡死。

## 待验证方向（不是定论）

1. Web 默认 4×MSAA、阴影、多光源及大量独立网格造成的渲染负担。
2. 第一次怀疑／追捕时动态灯光和边缘 Shader 的首次使用开销。
3. 高 DPI 下实际渲染负载、完整追捕及后续关卡。
4. 巡逻视野网格反复重建造成的 CPU／资源分配成本。

下一步应使用可稳定触发追捕的真实输入路线，在独立服务和浏览器中记录首次追捕前后的性能轨迹，再逐项进行对照实验。此前功能、音频测试通过不代表性能合格。

## 证据位置

项目内：`tests/web_freeze_probe.py`、`exports/evidence/freeze-detailed.json`、`exports/freeze-detailed.log`。

旧 baseline 将条件超时标记为不响应的判断有误，不应作为卡死证据；detailed 版已增加超时后真实响应探测。
