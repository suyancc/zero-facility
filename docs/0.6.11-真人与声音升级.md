# 0.6.11：真人主角、默认潜行配乐、完整交互过程声

## 本次范围

按用户确认的真人造型接入游戏：年轻男性、深色短发、灰白柔性上衣、深色长裤和小面积橙色织物标识。不再用机器人式硬质零件拼主角。其余 0.6.10 机器人、场景、设备缩略图与任务规则保留；没有新增未经确认的枪械、无人机、翻越等玩法。

同时修复平静游戏的配乐辨识度与长按 E 从开始到结束的过程声音。浏览器首次仍需点击或按键解锁声音；不重置用户已有的静音、音乐或心跳音量。

## 模型制作、许可与 Godot 接入

1. 在隔离工作区使用 Blender Python / MPFB 和官方 MakeHuman CC0 核心与系统素材构建角色；没有在用户电脑安装 Blender，也没有购买商业模型。
2. 先向用户展示实际三维模型的正面、侧面、面部及蒙皮步行草稿。用户选择“可以，继续接入”后才替换主角。
3. 运行模型 `assets/characters/maintenance_human.glb`，53 骨骼、6 个蒙皮网格、37,030 个三角形。来源明细及 CC0 许可证附在 `assets/licenses/makehuman/`。模型不是本项目从零独立创造的第三方资产；改造配色、材料和游戏动作由本项目完成。
4. 验收中发现 glTF 未烘焙人体形态导致皮肤穿出衣服、头发被遮挡。已将确认稿形态烘焙为真实顶点，移除运行文件中的所有 morph targets 与造型草稿动画。实际 Godot Web 截图再次检查通过，不拿 Blender 渲染代替实机结果。
5. `human_rig.gd` 根据移动速度、奔跑、蹲行、搬运、交互、被捕和逃生状态驱动实际骨骼。两段腿部 IK 保持足底接触，躯干前倾与手臂目标解算独立；不会改变碰撞胶囊、移动速度、存档身份、任务或消耗品数量。
6. 原有测试中针对旧“硬质分段节点”的检查已改为检查真实手掌、五指、腿部骨骼和鞋底；没有用空节点冒充可见人体通过验证。兼容控制节点仍承接玩家已有的动作接口，但新检查同时验证真实骨骼位置及 CPU 蒙皮后的顶点。
7. 48 个 idle/walk/run/sneak 采样姿态的 CPU 蒙皮鞋底最大偏差约 8.9 mm。此测试仅针对平坦关卡地面，不声称已经支持任意复杂坡道攀爬。

## 过程声音根因与修复

旧实现每帧设置 `stream_paused=false`，在 WebAudio 后端造成源反复重启。循环声又使用整秒 sin² 慢起音，短操作往往结束仍接近无声。隔离浏览器测试中，门声约 0.94 秒内启动 118 次，持续段约 −107 dBFS。

改为状态变化守卫、固定循环音高、仅停止活跃通道；新原始波形只有 2 ms 防咔哒起音，不再等待半秒才到峰值。八类波形对应 11 个操作类型，电子刷卡、锁具咔哒、数据脉冲、控制器、覆写、核心与搬运各有区别。

流程保持：按住 E 开始操作即发声 → 持续进度期间连续循环 → 释放/移动/暂停/取消立即清除 → 成功后停止过程通道并排入独立完成提示。完成提示、脚步、心跳仍是不同通道。背景配乐在交互时自动降低，给操作声留出空间。

隔离 Godot Web 测试使用真实键盘输入，在最终 WebAudio 输出节点采样 PCM，不只检查 AudioStreamPlayer.playing。11 种映射均只启动 1 个音源，初始 140 ms 和持续段都达到设定可闻范围，无削波；取消及暂停为静音，共 57 项断言通过。测试专用场景停止其他声音以隔离操作通道，并未删除或降低正式游戏的声音功能。

## 平静配乐

`compose_stealth_audio_v611.py` 原创合成低沉科幻潜行音乐：可听清的低中频和声、稀疏旋律、轻微脉动和回声，不再只是低频嗡声。15 秒 / 128 BPM 保持现有危险层的同步结构；发现、追逐和恢复混音继续工作。主音量、音乐与心跳独立设置和保存规则不变。

源生成器依赖 numpy / soundfile。用户 Python 3.11 缺少 soundfile，未擅自安装到其电脑；此次在隔离工作区生成后分块传输，通过 SHA-256 校验再替换。以后重跑旧的 remix_tension_audio.py 会覆盖 calm，因此需要最后运行本次生成器。

## 帧时结果与已知开销

在同一台 Windows 机器、独立 Chrome 上下文、1280×800、预热后各 6 秒采样，音乐保持开启：

|场景|0.6.10 平均 / P95|0.6.11 平均 / P95|
|---|---|---|
|平静站立|21.19 / 33.20 ms|28.26 / 41.60 ms|
|真实键盘往返行走|23.40 / 33.40 ms|29.87 / 41.60 ms|

真人蒙皮版本在此环境下有额外帧时成本，站立约 35 FPS、行走约 33 FPS（由平均帧时折算），**并未达到旧版性能**。优化前新版站立均值约 30.00 ms；通过静止姿态复用、只更新实际变化的 13 个局部骨骼、让手指继承手掌变换，避免每帧重解完整层级。优化后的姿态脚本开销均值约 26 μs（站立）/ 113 μs（移动），仍不能据此将剩余全部开销归因于某个具体 GPU 驱动因素。

本次没有降分辨率、隐藏场景物件、关闭音乐/心跳/灯光/阴影或减少动作刷新来制造提速结果。306→307 的测试变化是增加“人体形态已烘焙，无丢失 morph”的回归断言，不是减少测试。单机短样本不代表所有设备；此额外开销保留为后续性能优化事项。
